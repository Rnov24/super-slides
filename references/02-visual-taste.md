# Phase 2: Visual Taste Discovery and Token Definition Playbook

This playbook defines visual taste standards and token architecture for `super-slides`.

Decks generated by AI agents must look custom-crafted, intentional, and authoritative. Default-looking AI slop, flat untextured canvases, generic system-ui typography, and floating top-heavy layouts are banned.

---

## 1. The Core Visual Mandates

### Mandate A: Atmosphere Over Flat Surfaces (Flat Backgrounds Banned)
Flat, solid-color backgrounds without depth or atmosphere are strictly banned.
Every presentation canvas must establish an environmental surface:
- **Dark decks**: Use multi-stop radial gradients, dark ambient glows, subtle geometric grids (e.g., 64px or 80px hairline grids at 3% opacity), or dot-matrix textures.
- **Light decks**: Use warm tactile paper tones (such as `#f8f6f1` cream), subtle radial lighting washes, and hairline rules. Pure flat `#ffffff` with no texture or framing is prohibited.

### Mandate B: Distinctive Display Typography (System-UI Only Banned; Didone Faces Banned)
Generic system-ui display titles are banned.
Slide titles must use either:
1. An embedded distinctive web font (such as `Archivo Black`, `Sora`, `Syne`, or `Space Grotesk`).
2. A named classic serif stack with robust stroke weight (such as `Charter, "Bitstream Charter", "Sitka Text", Cambria, Georgia, serif`).

Display typography must have personality, commanding weight, and intentional letter-spacing.

#### The Projector-Legibility Rule:
High-contrast Didone display faces (Bodoni, Playfair, Didot, and similar typefaces with extreme thick-to-thin hairline strokes) are strictly BANNED for slide headers. Hairline strokes in Didone faces vanish when rendered at 1280px on conference projectors. All headers must remain legible and commanding at a 1280px render width. Permitted display faces have consistent, sturdy stroke weight: `Archivo Black`, `Sora 700`, `Space Grotesk`, and sturdy grotesques.

### Mandate C: Zero-Network Base64 Font Embedding
All presentations must remain 100% self-contained and run offline from `file://` with zero external HTTP requests.
Never link to Google Fonts or external CDNs in production decks.
Instead, embed woff2 font files directly into `<style>` using base64 data URIs:
```css
@font-face {
  font-family: 'Sora';
  font-style: normal;
  font-weight: 700;
  font-display: swap;
  src: url(data:font/woff2;base64,d09GMgABAAAA...) format('woff2');
}
```

#### Procedure for Font Fetching and Embedding:
1. **Primary route**: Fetch the woff2 file from the Google Fonts API using curl or python with a modern browser User-Agent header to receive the latin woff2 slice (e.g., Sora 700, Archivo Black, Space Grotesk, DM Sans).
2. **Secondary route**: If Google Fonts API is unreachable, use `npm pack` into a temporary directory (e.g. `/tmp/fonts`) for Fontsource packages (such as `@fontsource/sora` or `@fontsource/archivo-black`), extract the woff2 file, and remove the temp directory. Never install npm packages into the project workspace.
3. **Subsetting**: If full font files are obtained, subset to the latin range (U+0000-00FF plus standard punctuation) using `python3 -m fontTools.subset` to keep base64 payload under 50KB per face.
4. **Encoding**: Convert the woff2 binary into a base64 string and embed via `@font-face` with `font-display: swap`.
5. **Fallback route**: If external font retrieval fails completely, use the closest distinctive system font stack (Charter, Cambria, Georgia for editorial serif; Cascadia Code, Consolas for engineering mono; Space Grotesk 700 if available) and explicitly document the fallback in the generation report. Never silently emit generic system sans-serif.

### Mandate D: Action Titles (Conclusion-Led Headlines)
Every slide title must be an action title that states the conclusion, insight, or thesis of that slide.
- **Banned topic labels**: "Overview", "Architecture", "The Problem", "System Metrics", "Next Steps", "Comparison".
- **Required action titles**:
  - "Direct GPU Compositing Eliminates DOM Reflow Latency"
  - "Three Architectural Bottlenecks Break AI Presentation Decks"
  - "Sub-Minute Signal Latency Accelerates Operational Decisions"
  - "Zero Runtime Dependencies Guarantee Offline Conference Execution"

### Mandate E: Full-Height Vertical Content Span & Distribution Rules (R-11)
Every slide must utilize the full 1080px canvas height with deliberate vertical rhythm. The visible content span — measured from the top of the kicker to the bottom of the last content element (excluding the deck footer) — must be at least 65% of the 1080px canvas height (≥ 702px).

#### The Three Mechanical Distribution Checks:
1. **No Overflow**: Every visible text element's INK (measured with `Range.getBoundingClientRect()`, not the element box) must lie fully inside the 1920×1080 stage boundaries (`right <= 1920px`, `bottom <= 1080px`). Element boxes do not catch text overflowing its own column.
2. **No Internal Void**: In stacked content flows only (rows, sequences, comparison lists, metrics rows, problem blocks), the vertical gap between consecutive visible content elements must not exceed 150px anywhere (`maxInternalGap <= 150px`). Pole layouts (hero, closing, quote, split) and terminal/code boxes are exempt: their pole gap and centered text are the design, not a void.
3. **Content Span ≥ 65%**: `span = maxBottom - minTop >= 702px` across content elements.

#### Warning Against Naive `space-between` Voids:
Using `justify-content: space-between` with only two or three sparse groups creates massive internal voids (> 200-300px) by pushing content to the extreme top and bottom edges of the canvas.
- **Do not isolate kickers**: Never let `space-between` trap a kicker at the very top with 200px of void below it. Group the kicker, headline, and primary statement into a continuous typographic block.
- **Group related elements**: Group the kicker, headline, and rules into one top block, and sub-elements into a second block with balanced, moderate spacing (40px to 96px).
- **Scale typography and container heights**: Scale display type up aggressively (hero titles ~120-150px, giant figures ~240-280px, metric numerals ~180-200px, sequence numbers ~100-112px, row titles ~40-44px). Increase track heights and row paddings so content naturally spans ≥ 65% without artificial chasms.
- **Scale SVG diagrams**: Inline SVG diagrams must occupy ~80% of canvas area with large, clear node typography (20px+) legible at 1280px.
- **Never add filler copy**: Fill canvas height by scaling and distributing, never by adding filler sentences, extra bullets, or decorative card boxes.
- **Stage integrity (R-17)**: `#deck-viewport` is `display: flex`, so the 1920px `.deck-canvas` must carry `flex-shrink: 0` or it shrinks to the viewport width at any window narrower than 1920px and the whole deck renders squished. The matrix scale (`--deck-scale`) is the only mechanism that adapts the stage to the viewport.

### Mandate F: At Least One Graphic Device Per Deck
Every deck must feature at least one signature graphic device that unifies the slides:
- **Bold section numerals**: Large numeric identifiers (such as `01`, `02`) in display typography.
- **Structural rules and dividers**: Distinctive 4px colored accent bars or fine hairline grid frames.
- **Architectural registry marks**: Coordinate stamps, crosshair registration marks (`+`), or pill badges.
- **Directional focal cards**: A high-contrast colored card (such as `#FF5722` orange) commanding attention on the canvas.

### Mandate G: Strict Em-Dash Ban (R-05)
Never use em-dashes in slide titles, subtitles, card headers, or body text.
Use colons, commas, periods, or parentheses to separate clauses cleanly.

### Mandate H: Layout Variety (Max 1 Card Grid Per Deck)
Repetitive card grids across multiple slides make decks read as default AI templates.
Rules:
- At most one card grid per deck.
- No two consecutive slides may share the same structural layout.
- Build varied, full-height compositions: Hero statements with proof rows, full-width numbered feature rows, two-column split comparisons with center rules, horizontal step sequences (01→04) joined by arrows, full-bleed diagrams without container cards, full-bleed code terminals, and standalone metric columns.

### Mandate I: Strict Copy Budget (≤40 Body Words Per Slide)
Slide copy must be concise, punchy, and instantly scannable:
- Body copy per slide must not exceed 40 words (action titles, kickers, and slide numbers are excluded from this count).
- No paragraph may exceed two lines.
- Illustrative disclaimers must collapse to at most one single footer line per deck ("All figures illustrative").
- Cut filler copy ruthlessly rather than shrinking font sizes or falling back to box cards.

## 2. Curated Style Presets

### Preset 1: Bold Signal (Technical and Engineering Decks)
- **Mood**: Confident, high-velocity, modern, high-impact.
- **Palette**:
  - `--bg`: `#0a0d12` (dark radial gradient to `#141820`)
  - `--surface`: `#121822`
  - `--surface-border`: `#222d3d`
  - `--text`: `#f0f6fc`
  - `--text-muted`: `#8b949e`
  - `--accent`: `#FF5722` (committed focal orange)
  - `--accent-alt`: `#38bdf8` (electric cyan secondary)
- **Typography**:
  - Display: `Archivo Black` (embedded base64 woff2)
  - Body & Subheads: `Space Grotesk` (embedded base64 woff2)
  - Code: Monospace stack (`Cascadia Code`, `Consolas`)
- **Graphic Device**: Vibrant orange focal card, large section numbers (`01`), subtle geometric background grid.

### Preset 2: Elevated Light Editorial (Executive and Pitch Decks)
- **Mood**: Authoritative, literary, thoughtful, prestigious.
- **Palette**:
  - `--bg`: `#f8f6f1` (warm cream paper with subtle radial lighting)
  - `--surface`: `#ffffff`
  - `--surface-border`: `#e6e2d9`
  - `--text`: `#1a1a1a` (deep ink)
  - `--text-muted`: `#5a554e` (charcoal stone)
  - `--accent`: `#b33927` (terracotta crimson)
  - `--accent-alt`: `#2b5c54` (deep pine green)
- **Typography**:
  - Display: `Sora 700` (embedded base64 woff2)
  - Body & Subheads: `DM Sans` (embedded base64 woff2)
  - Labels & Coordinates: `JetBrains Mono` or `Consolas`
- **Graphic Device**: Terracotta accent bars, architectural hairline rules, notebook tabs, and clean metric cards.

### Preset 3: High-Contrast Engineering Terminal
- **Mood**: Precision infrastructure, developer-native, zero-noise.
- **Palette**:
  - `--bg`: `#000000` (deep basalt with fine grid)
  - `--surface`: `#0d1117`
  - `--surface-border`: `#30363d`
  - `--text`: `#f0f6fc`
  - `--text-muted`: `#c9d1d9`
  - `--accent`: `#58a6ff` (terminal cyan)
  - `--accent-alt`: `#3fb950` (terminal green)
- **Typography**:
  - Monospace font stack exclusively (`Cascadia Code`, `Fira Code`, `JetBrains Mono`).

## 3. WCAG 4.5:1 Contrast Floor

Every text element must maintain a minimum contrast ratio of 4.5:1 against its background container:
$$\text{Contrast Ratio} = \frac{L_1 + 0.05}{L_2 + 0.05}$$

- Never use low-contrast gray text on dark backgrounds.
- Never place muted accent text directly on bright colored badges.
- Ensure dark surfaces retain sufficient contrast under washed-out conference projector conditions.

## 4. Gate 2: Human Sign-Off Protocol

Before generating presentation markup, output the selected design system tokens, typography choices, and slide action-title outline for human approval.

### Gate 2 Checklist:
- [ ] Atmospheric background defined (gradients, subtle grids; no flat solid fills).
- [ ] Display font embedded as base64 woff2 or named serif stack (no system-ui only).
- [ ] Every slide has a conclusion-led action title.
- [ ] Layouts utilize full 1080px height without bottom dead space.
- [ ] At least one signature graphic device established.
- [ ] Contrast floor of 4.5:1 validated.
