# Dual-Modality Interaction & Motion Architecture

* **Author:** @rnov24
* **Status:** Proposed
* **Date:** 2026-11-14

--------------------------------------------------------------------------------

## Overview

Presentation slides generated by AI coding agents frequently suffer from one of two extremes: either instant, jarring cuts on keypress (e.g., `frontend-slides`) or intrusive floating control docks and heavy script engines (e.g., Reveal.js) that obstruct in-slide interactive elements.

This specification defines a dual-modality interaction and motion architecture for `super-slides`. It establishes an explicit boundary between two operational planes:

1. **Macro Presentation Navigation (Keyboard/Swipe Driven)**: Controls directional slide-push transitions using hardware-composited `translate3d` transforms, directional cubic-bezier easing (280ms), pointer-event hit-test suppression during motion, single-flight transition locking with target-index coalescing, and dual-trigger safety timeouts.
2. **Micro In-Slide Interactivity (Mouse/Pointer Driven)**: Allocates the slide canvas exclusively to internal interactive components—such as hover reveals, expanding bento cards, SVG node highlighting, and tabbed inspectors—without visual obstruction or event collisions from persistent floating docks.

The architecture is implemented in vanilla HTML5, CSS3, and JavaScript (<150 LOC) with zero external runtime dependencies.

## The Problem

Current presentation approaches fail to balance presenter navigation with rich interactive content in four ways:

1. **Compositor Hit-Test Drops During Motion**: When sliding across complex DOM structures (e.g., 100+ SVG nodes or cards with backdrop filters), a stationary mouse cursor triggers continuous hit-testing and style recalculations, dropping framerates below 60 FPS.
2. **Navigation and Widget Keybinding Collisions**: Interactive widgets inside slides (such as tab lists, collapsible cards, or forms) can capture key events and prevent the presenter from advancing slides, or conversely, global listeners can jump slides when a user intends to interact with an in-slide widget.
3. **Screen Clutter and Mis-Clicks from Floating Docks**: Persistent floating navigation bars and overlay arrows consume screen space, obstruct lower-row bento cards, and cause accidental slide transitions when clicking near slide margins.
4. **Transition Race Conditions and Minimized-Tab Freezes**: Rapid key mashing can spawn overlapping animations or queue an unresponsive animation backlog. Furthermore, browsers suspend CSS `transitionend` events when a tab is backgrounded, causing single-flight locks to freeze permanently in transition state.

## Goals

* **Modality Separation**: Strictly divide macro navigation (keyboard and edge swipe) from micro interactivity (pointer clicks and hover within slide elements), eliminating all persistent floating control docks.
* **Deterministic Directional Motion**: Deliver hardware-composited horizontal slide transitions (`translate3d(x, 0, 0)`) with directional offset (+100% next, -100% previous) over 280ms with `cubic-bezier(0.2, 0.8, 0.2, 1.0)`.
* **Compositor Hit-Test Isolation**: Guarantee 60 FPS by enforcing `pointer-events: none !important` via a root `.is-transitioning` class during macro animations, suppressing cursor hit-testing over complex SVGs and bento grids.
* **Race Condition and Freeze Protection**: Prevent state desynchronization via a single-flight lock with target-index coalescing, paired with a companion fallback timer (`setTimeout` for duration + 40ms) that resolves even if `transitionend` is dropped.
* **Touch-Gesture Parity with Micro-Scroll Exceptions**: Support directional touch swipe navigation (`|deltaX| > 40px` and `|deltaX| > 1.5 * |deltaY|` within 300ms) while allowing inner scrollable containers (e.g., code blocks, metric carousels) to opt out using `data-prevent-slide-swipe`.
* **Zero External Dependencies**: Implement the entire motion and interaction architecture using standard HTML5, CSS3, and vanilla JavaScript in under 150 lines of code.
* **Reduced Motion Compliance**: Instantly bypass all transitions to 0ms cuts when `prefers-reduced-motion: reduce` is detected or when an individual slide declares `data-transition="cut"`.

## Non-Goals

* **No Floating Control Docks**: No persistent navigation buttons, floating docks, or arrow overlays in default presentation view. An on-demand shortcut HUD is accessible only via `?` key or a corner tap-target.
* **No Animation Queuing**: No sequential queuing of keypress transitions; subsequent inputs coalesce to the final target index immediately.
* **No Physics Simulation Engines**: No spring physics, bounce dynamics, or WebGL transitions.
* **No Global Mousewheel Scroll-Jacking**: Mousewheel vertical scrolling will not advance slides, preventing conflicts with scrollable code blocks or text panels.
* **No Third-Party Runtime Dependencies**: No animation frameworks (e.g., GSAP, Framer Motion) or gesture libraries.

## Open Questions

* **Question 1**: Should the on-demand shortcut HUD (`?` key) share styling with the presenter speaker notes HUD (`N` key) or remain a distinct, minimal keyboard badge overlay?
* **Question 2**: For slides declaring `data-transition="cut"`, should incoming slides skip layer promotion (`will-change: transform`) entirely to minimize memory overhead on mobile browsers?

## Critical User Journeys (CUJs)

### CUJ 1: Keyboard Macro Navigation with Active Interactive Slide

* **Given**: A slide featuring an interactive 4-card bento grid with hover reveals and an active tabbed code inspector.
* **When**: The presenter presses `ArrowRight` or `Space` while their mouse cursor hovers over one of the interactive bento cards.
* **Then**: The window capture listener intercepts the key event, attaches `.is-transitioning` to `#deck-viewport` (enforcing `pointer-events: none !important`), promotes the active and incoming slides with `will-change: transform`, and executes a 280ms horizontal slide translation via `translate3d`. The stationary mouse cursor produces zero hit-test recalculations during motion. Once settled, the transition lock and `.is-transitioning` are removed, immediately restoring pointer responsiveness.

### CUJ 2: Rapid Keypress Coalescing During Active Transition

* **Given**: The deck is at Slide 2 and an active transition toward Slide 3 is underway (at elapsed time 90ms).
* **When**: The presenter rapidly presses `ArrowRight` twice more in quick succession.
* **Then**: The engine does not spawn parallel animation threads or queue up successive 280ms delays. Instead, it coalesces the target index to Slide 4, immediately completes the departure of Slide 2, and dynamically routes the incoming slide animation directly toward Slide 4. The transition terminates at Slide 4 cleanly without an accumulated latency backlog.

### CUJ 3: Background Tab Recovery via Safety Fallback Timer

* **Given**: A presenter advances to Slide 5 just as they switch browser tabs or minimize the presentation window.
* **When**: The browser engine throttles background timers and suspends the standard CSS `transitionend` DOM event.
* **Then**: The internal companion safety timer (`setTimeout(duration + 40ms = 320ms)`) fires, stripping `.is-transitioning`, resetting `isTransitioning = false`, clearing `will-change` layer promotions, and synchronizing `window.location.hash = #slide-5`. The presentation state remains unlocked and functional when the tab is reopened.

### CUJ 4: Touch Swipe on a Slide with Horizontal Scroll Containers

* **Given**: A slide containing a wide, horizontally scrollable code block or metric table marked with `data-prevent-slide-swipe`.
* **When**: A mobile or tablet user drags their finger horizontally across the code block.
* **Then**: The touch listener detects `e.target.closest('[data-prevent-slide-swipe]')` and allows native horizontal element scrolling without intercepting the gesture. When a swipe is performed outside of this container, the macro engine validates the displacement threshold (`|deltaX| > 40px` and `|deltaX| > 1.5 * |deltaY|`) and triggers a slide-push transition.

## Technical Plan (Architecture)

### 1. Architectural Modality & Viewport Layer Model

The deck presentation space is organized into two isolated functional layers:
1. **The Navigation Plane**: Manages slide mounting, visibility virtualization, transform translation, and pointer hit-test suppression at the root `#deck-viewport` level.
2. **The Content Canvas Plane**: Houses all slide content (typography, bento cards, inline SVGs, interactive controls), operating within an isolated coordinate system with no awareness of adjacent slides.

```text
+-----------------------------------------------------------------------------------+
| #deck-viewport (16:9 Letterbox Container, position: relative, overflow: hidden)   |
|   Classes: [.is-transitioning (transient)]                                        |
+-----------------------------------------------------------------------------------+
  |
  +-- <section class="slide slide-prev" data-layout="..."> (Hidden / Offscreen -100%)
  |
  +-- <section class="slide slide-current" data-layout="..."> (Active at 0, 0, 0)
  |     |-- Interactive Bento Cards (:hover, :active micro-animations)
  |     |-- Interactive Tab Controls (click-to-toggle inspection)
  |     +-- Inline Native SVG Diagrams (cursor hover highlights)
  |
  +-- <section class="slide slide-incoming" data-layout="..."> (Entering from +100%)
  |
  +-- <section class="slide slide-idle" data-layout="..."> (Virtualised: content-visibility: hidden)
  |
  +-- #shortcut-hud.hud-overlay (On-demand key guide, toggled by `?`, default hidden)
```

### 2. Transition Mechanics & CSS Invariants

All slide transitions rely exclusively on hardware-composited 3D transforms (`translate3d`) to prevent CPU layout reflows.

#### A. Transition Timing Curve
* **Duration**: 280ms
* **Timing Function**: `cubic-bezier(0.2, 0.8, 0.2, 1.0)` (swift acceleration with a smooth, natural deceleration shelf)
* **Reduced Motion**: If `@media (prefers-reduced-motion: reduce)` is satisfied or the slide carries `data-transition="cut"`, the transition duration drops to `0.001ms !important`, executing an instant cut.

#### B. CSS Class State Contract
```css
/* Viewport and Hit-Test Suppression */
#deck-viewport {
  position: relative;
  width: 1920px;
  height: 1080px;
  overflow: hidden;
  background: var(--bg);
}

#deck-viewport.is-transitioning {
  pointer-events: none !important;
  user-select: none !important;
}

/* Slide Base Stacking */
.slide {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  display: flex;
  flex-direction: column;
  transform: translate3d(100%, 0, 0);
  visibility: hidden;
  content-visibility: hidden;
}

/* Active & Visible States */
.slide.slide-current {
  transform: translate3d(0, 0, 0);
  visibility: visible;
  content-visibility: visible;
  z-index: 2;
}

/* Layer Promotion & Motion Application */
#deck-viewport.is-transitioning .slide.slide-current,
#deck-viewport.is-transitioning .slide.slide-incoming {
  visibility: visible;
  content-visibility: visible;
  will-change: transform;
  transition: transform 280ms cubic-bezier(0.2, 0.8, 0.2, 1.0);
}

/* Directional Shift Targets */
.slide.slide-exit-left {
  transform: translate3d(-100%, 0, 0) !important;
}

.slide.slide-exit-right {
  transform: translate3d(100%, 0, 0) !important;
}

.slide.slide-enter-active {
  transform: translate3d(0, 0, 0) !important;
}

@media (prefers-reduced-motion: reduce) {
  #deck-viewport.is-transitioning .slide.slide-current,
  #deck-viewport.is-transitioning .slide.slide-incoming {
    transition-duration: 0.001ms !important;
  }
}
```

### 3. Transition Lifecycle & Target Coalescing Flow

The execution cycle guarantees that duplicate keystrokes coalesce cleanly into the terminal target index without creating concurrent animation conflicts or state desynchronization.

```mermaid
sequenceDiagram
    autonumber
    actor Presenter
    participant Window as Window (Capture Phase)
    participant Engine as Motion Engine
    participant Viewport as #deck-viewport DOM
    participant ActiveSlide as Current Slide
    participant TargetSlide as Target Slide

    Presenter->>Window: Press ArrowRight (or swipe left)
    Window->>Engine: onKeyDown (Capture: true)
    
    alt isTransitioning == true
        Engine->>Engine: Coalesce Target: targetIndex = min(targetIndex + 1, maxIndex)
        Note over Engine: Target coalesced; no concurrent transition spawned
    else isTransitioning == false
        Engine->>Engine: Set isTransitioning = true, targetIndex = currentIndex + 1
        Engine->>Viewport: Add class .is-transitioning (pointer-events: none)
        Engine->>ActiveSlide: Prepare exit class (.slide-exit-left)
        Engine->>TargetSlide: Set initial position (+100%) & add .slide-incoming
        Engine->>TargetSlide: Force reflow & apply .slide-enter-active
        
        par Parallel Completion Guards
            ActiveSlide->>Engine: transitionend event
        and
            Engine->>Engine: Fallback timer (setTimeout 320ms)
        end
        
        Engine->>Engine: finalizeTransition()
        Engine->>Viewport: Remove class .is-transitioning
        Engine->>ActiveSlide: Remove .slide-current, .slide-exit-left, clear will-change
        Engine->>TargetSlide: Add .slide-current, remove .slide-incoming, clear will-change
        Engine->>Engine: Update currentIndex = targetIndex, set isTransitioning = false
    end
```

### 4. JavaScript Motion & Input Controller Architecture

The controller is encapsulated in a lean, zero-dependency class (<140 lines) embedded directly in `templates/deck-skeleton.html`.

#### Key Responsibilities & Data Structures:
* **State Properties**:
  * `currentIndex`: Zero-based index of the currently settled slide.
  * `targetIndex`: Target slide index during single-flight or coalesced transitions.
  * `isTransitioning`: Boolean flag locking the transition pipeline.
  * `safetyTimer`: ID of the fallback `setTimeout` to recover from dropped `transitionend` events.
  * `touchState`: Coordinates and timestamp tracking active touch gestures (`startX`, `startY`, `startTime`).

#### API Specification:
```javascript
class SlideMotionController {
  constructor(viewportEl, slideElements, options = {}) {
    this.viewport = viewportEl;
    this.slides = Array.from(slideElements);
    this.currentIndex = 0;
    this.targetIndex = 0;
    this.isTransitioning = false;
    this.safetyTimer = null;
    this.duration = options.duration || 280;
    this.touchState = { startX: 0, startY: 0, startTime: 0 };

    this.bindEvents();
    this.initSlidePositions();
  }

  bindEvents() {
    // Window Capture Phase Key Binding
    window.addEventListener('keydown', (e) => this.handleKeyDown(e), { capture: true });

    // Touch Gesture Support
    this.viewport.addEventListener('touchstart', (e) => this.handleTouchStart(e), { passive: true });
    this.viewport.addEventListener('touchend', (e) => this.handleTouchEnd(e), { passive: false });
  }

  handleKeyDown(e) {
    // Exclude text inputs from hijacking
    if (e.target.matches('input, textarea, [contenteditable="true"]')) return;

    switch (e.key) {
      case 'ArrowRight':
      case 'PageDown':
      case ' ':
        e.preventDefault();
        this.navigate(1);
        break;
      case 'ArrowLeft':
      case 'PageUp':
      case 'Backspace':
        e.preventDefault();
        this.navigate(-1);
        break;
      case 'Home':
        e.preventDefault();
        this.goTo(0);
        break;
      case 'End':
        e.preventDefault();
        this.goTo(this.slides.length - 1);
        break;
      case '?':
        e.preventDefault();
        this.toggleShortcutHUD();
        break;
    }
  }

  navigate(direction) {
    const nextTarget = Math.max(0, Math.min(this.slides.length - 1, (this.isTransitioning ? this.targetIndex : this.currentIndex) + direction));
    if (nextTarget === this.currentIndex && !this.isTransitioning) return;
    this.goTo(nextTarget, direction);
  }

  goTo(targetIndex, explicitDirection = null) {
    if (targetIndex < 0 || targetIndex >= this.slides.length || targetIndex === this.currentIndex) return;

    if (this.isTransitioning) {
      // Coalesce target index without restarting transition
      this.targetIndex = targetIndex;
      return;
    }

    this.targetIndex = targetIndex;
    const direction = explicitDirection !== null ? explicitDirection : (targetIndex > this.currentIndex ? 1 : -1);
    this.executeTransition(this.currentIndex, this.targetIndex, direction);
  }

  executeTransition(fromIndex, toIndex, direction) {
    this.isTransitioning = true;
    this.viewport.classList.add('is-transitioning');

    const fromSlide = this.slides[fromIndex];
    const toSlide = this.slides[toIndex];
    const isInstantCut = fromSlide.dataset.transition === 'cut' || toSlide.dataset.transition === 'cut' || window.matchMedia('(prefers-reduced-motion: reduce)').matches;

    if (isInstantCut) {
      fromSlide.classList.remove('slide-current');
      toSlide.classList.add('slide-current');
      this.finalize(toIndex);
      return;
    }

    // Set initial position of incoming slide
    toSlide.style.transform = `translate3d(${direction * 100}%, 0, 0)`;
    toSlide.classList.add('slide-incoming');
    toSlide.getBoundingClientRect(); // Force style recalibration

    // Apply translation targets
    fromSlide.classList.add(direction > 0 ? 'slide-exit-left' : 'slide-exit-right');
    toSlide.classList.add('slide-enter-active');

    let resolved = false;
    const onComplete = () => {
      if (resolved) return;
      resolved = true;
      if (this.safetyTimer) clearTimeout(this.safetyTimer);
      toSlide.removeEventListener('transitionend', onComplete);
      this.cleanupTransition(fromSlide, toSlide);
      this.finalize(toIndex);
    };

    toSlide.addEventListener('transitionend', onComplete, { once: true });
    // Dual safety fallback timeout
    this.safetyTimer = setTimeout(onComplete, this.duration + 40);
  }

  cleanupTransition(fromSlide, toSlide) {
    fromSlide.classList.remove('slide-current', 'slide-exit-left', 'slide-exit-right');
    toSlide.classList.remove('slide-incoming', 'slide-enter-active');
    toSlide.classList.add('slide-current');
    toSlide.style.transform = '';
    fromSlide.style.transform = '';
    this.viewport.classList.remove('is-transitioning');
  }

  finalize(finalIndex) {
    this.currentIndex = finalIndex;
    this.isTransitioning = false;
    window.location.hash = `#slide-${finalIndex + 1}`;

    // If target coalesced during the previous transition, immediately initiate next hop
    if (this.targetIndex !== this.currentIndex) {
      const nextHop = this.targetIndex;
      this.targetIndex = this.currentIndex;
      this.goTo(nextHop);
    }
  }

  handleTouchStart(e) {
    if (e.target.closest('[data-prevent-slide-swipe]')) return;
    const touch = e.changedTouches[0];
    this.touchState = { startX: touch.clientX, startY: touch.clientY, startTime: Date.now() };
  }

  handleTouchEnd(e) {
    if (e.target.closest('[data-prevent-slide-swipe]')) return;
    const touch = e.changedTouches[0];
    const deltaX = touch.clientX - this.touchState.startX;
    const deltaY = touch.clientY - this.touchState.startY;
    const elapsedTime = Date.now() - this.touchState.startTime;

    if (elapsedTime <= 300 && Math.abs(deltaX) > 40 && Math.abs(deltaX) > 1.5 * Math.abs(deltaY)) {
      if (deltaX < 0) this.navigate(1);
      else this.navigate(-1);
    }
  }

  toggleShortcutHUD() {
    let hud = document.getElementById('shortcut-hud');
    if (!hud) return;
    hud.classList.toggle('visible');
  }
}
```

### 5. Micro In-Slide Interactivity Guarantees

By strictly sequestering macro slide movement to the `SlideMotionController`:
* **Zero Visual Obstruction**: The entire 1920x1080 canvas is free from sticky bottom docks, floating arrow chips, and modal chrome.
* **Full Event Bandwidth**: In-slide elements handle all mouse events (`click`, `mouseenter`, `mouseleave`, `mousemove`) natively without event interception or bubbling suppression from deck-level controls.
* **Component Styling Archetypes**: Bento card hover highlights, expanding accordion sections, interactive SVG graph node filters, and live syntax inspection tabs function with complete DOM isolation.

## Alternatives Considered

### Alternative A: Native CSS View Transitions API (`document.startViewTransition`)

* **Pros**: Native declarative browser primitive; eliminates the need for manual class manipulation and reflow-flushing hacks.
* **Cons**: Browser support is inconsistent in embedded webviews, older headless environments, and enterprise browsers. Coordinating directional slide-push transforms requires configuring dynamic CSS pseudo-elements (`::view-transition-group`, `::view-transition-old`, `::view-transition-new`) on every navigation direction change, adding CSS complexity. Does not cleanly enforce pointer-event hit-test suppression during capture.
* **Reason for Rejection**: Rejected by author: native View Transitions support varies across older browser engines and embedded runtimes, and lacks granular directional control without verbose CSS pseudo-elements. The standard CSS transform-class architecture ensures universal offline compatibility with zero polyfills or browser version caveats.

### Alternative B: Sequential Animation Queuing

* **Pros**: Preserves every keystroke event in order, guaranteeing that an exact sequence of keypresses translates into an exact sequence of slide shifts.
* **Cons**: If a presenter presses `ArrowRight` five times rapidly, a sequential queue locks the interface for 1.4 seconds (5 * 280ms) while playing out intermediate animations. The presenter cannot halt or reverse the deck until the entire queue finishes.
* **Reason for Rejection**: Rejected by author: queuing keypress animations produces unacceptable interface latency and deprives the presenter of real-time control. Target coalescing with single-flight locking commits or redirects immediately to the latest intended slide.

### Alternative C: Persistent Floating Bottom Navigation Dock

* **Pros**: Exposes persistent visual buttons for advancing or reversing slides with a mouse.
* **Cons**: Consumes 48–64px of vertical screen real estate, causes visual clutter during presentations, and leads to mis-clicks when users interact with bento cards or buttons located in the lower third of the canvas.
* **Reason for Rejection**: Rejected by author: persistent chrome obstructs presentation content, degrades visual immersion, and collides with in-slide interactive targets. It is replaced by keyboard keybindings, touch gestures, and an on-demand shortcut HUD toggled via the `?` key.

### Alternative D: Global Mousewheel Scroll-Jacking

* **Pros**: Allows trackpad and mousewheel users to flick through slides without touching the keyboard.
* **Cons**: Hijacking wheel events severely interferes with slide components that require local scrolling (e.g., syntax-highlighted code panels, long JSON dumps, or horizontally scrollable architecture diagrams). Inertial scrolling on macOS trackpads frequently triggers multiple accidental slide transitions.
* **Reason for Rejection**: Rejected by author: intercepting vertical mouse wheel events breaks native scrolling ergonomics for inner content widgets. Mousewheel slide navigation is explicitly excluded from the core runtime.

## Non-Functional Requirements

### 1. Performance & Frame Budget
* **Frame Rate Budget**: All slide transitions must sustain 60 FPS (<=16.6ms frame time) on standard hardware, achieved by isolating animations to GPU-composited `transform: translate3d(...)` and enforcing `pointer-events: none !important` via `.is-transitioning`.
* **Runtime Footprint**: The entire interaction and motion controller must not exceed 150 lines of unminified vanilla JavaScript (<5KB), maintaining zero external dependencies.
* **Cold Start Overhead**: The transition controller must initialize in <5ms during initial DOM load.

### 2. Accessibility
* **Reduced Motion**: When `prefers-reduced-motion: reduce` is active, the engine sets transition durations to `0.001ms !important`, delivering instantaneous slide cuts without motion sickness triggers.
* **Screen Reader Announcer**: Slide index transitions update an ARIA live region (`#deck-announcer[aria-live="polite"]`) announcing `"Slide X of Y"` upon transition settlement.
* **Focus Restoration**: Keyboard focus is maintained on the active slide container (`<section class="slide" tabindex="-1">`) so screen reader navigation flows naturally into the active slide content.

### 3. Reliability & Edge Cases
* **Background Tab Recovery**: The companion safety timer (`setTimeout(duration + 40ms)`) guarantees that backgrounded or minimized browser tabs never become permanently locked in an `isTransitioning = true` state.
* **DOM Boundary Isolation**: Input listeners on the window object must inspect `e.target` and yield immediately if focus is within an editable text input (`input`, `textarea`, `[contenteditable]`), preventing form interaction lockouts.
